# Library 与 Canon 的隔离

Status: proposed
Sources: SRC-001, SRC-002, SRC-004

P5/P6 为已接受原则；本页对象关系和流程属于细化提案。历史例子的名字不是全局命名标准。

## 四种身份不能混淆

| 内容 | 作用域 | 允许的变化 |
| --- | --- | --- |
| Library 原版 | 可复用素材的某版本 | 单独审阅的素材修订 |
| Story Instance | 某故事中的实例 | 该故事范围内候选/已确认变化 |
| Derivation | 来源版本到派生结果的关系 | 记录来源，不能隐含回写权限 |
| Story Canon | 作者确认的故事/分支事实版本 | 仅应用作者明确接受的变更 |

## 血人案例

素材“血人001”版本 L1 派生到故事 A 的“血人001-A”。它在故事 A 中获得新能力，可用“血人001-A-01”解释衍生结果，但实际 ID/版本格式待定。原版 L1 和故事 B 从 L1 派生的实例都不因这段经历变化。

如果 Library 后来产生 L2，已有 A/B 实例不自动接受更新。应比较变化并让作者选择是否生成各自更新提案。若作者把 A 的变化抽象成可复用素材，新建 Library 候选版本，保留来源并另行确认。

## 实现候选及风险

快照复制简单但可能重复数据；固定版本引用加覆盖有利于来源关联但需处理升级差异。这是逻辑取舍分析，尚未实验或选型。共享可变实例并自动反向同步违反隔离。

素材本身的小说内描述是数据，不能作为工具操作指令。Context Engine 检索到其他作品的实例时不能把它冒充当前故事事实。
