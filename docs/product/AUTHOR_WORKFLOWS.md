# 作者工作流与最小产品路径

Status: proposed_product_design  
Updated: 2026-09-14  
Sources: SRC-001–SRC-008

本页从作者视角描述 V5 怎样工作。它定义操作含义，不锁定具体 UI 框架。

## 1. 首页

作者看到作品、最近场景、待处理 Canon 提案、活跃线程和最近任务。每个作品显示当前分支和版本。创建入口允许选择：只有想法、已有设定、已有大纲、已经写作、导入完整小说。

系统不要求先选题材或平台。题材标签只帮助推荐 Capability；作者可以随时组合或关闭能力。

## 2. 故事孵化

输入一句想法后，系统先展示核心幻想、压力、循环、问题和可能的读者承诺，再提供多个可组合方向。作者选择、修改或保留未定项；只有明确确认的内容进入 Story Core/Canon，其他内容保持 draft/proposed。

完成条件不是填满模板，而是当前第一个场景所需的关键事实和意图足够清楚。

## 3. 规划空间

同一数据提供多种视图：

- Story Spine：拿掉就会改变作品身份的关键变化；
- Thread Board：主线、人物、关系、谜团、伏笔和期待的生命周期；
- Arc/Volume：阶段目标、约束、承诺和风险；
- Chapter Mission：本章让读者经历什么；
- Scene Plan：POV、目标、阻力、转折、信息和退出变化；
- Plan vs Actual：计划、实际发生和偏离原因并列。

拖动计划节点改变 placement，不修改已经发生的 Event。对旧正文产生影响时，先形成修改提案。

## 4. 场景写作

页面中央是正文；侧栏显示 Scene Mission、POV 当前状态、人物所知、地点规则、活跃线程和近期原文。Context Inspector 可展开查看模型本次实际收到的材料、来源和截断项。

作者可以要求续写、改写、缩写、对话增强或审查。每次请求先形成 Task Contract；系统只读取与任务相关且被授权的资料。

输出分三层：正文草稿、审查发现、候选事实变化。三者不会合成一个含糊的“接受全部”。

## 5. Canon Inbox

候选变化按原子差异展示：

- 顾沉.location：北城门 → 实验室；
- 舌枪.owner：顾沉 → 林晚；
- 林晚对“张教授是幕后者”：unknown → suspects；
- Thread-07：developing → escalating。

每项显示正文锚点、来源、影响范围、冲突和相关后续。作者可接受、拒绝、搁置或编辑。基线变化后原批准失效，必须查看新差异。

## 6. Story Bible

Bible 是方便阅读和编辑的 Canon 投影，包括人物、世界、规则、物品、组织和关系。页面标出 Canon、计划、推断和缺失字段。编辑 Bible 时生成候选变更；不会绕过 Inbox 直接覆盖历史。

## 7. 修改旧章

系统先建立影响预览：后续哪些场景引用该事实、哪些人物知识变化、哪些线程兑现失效、哪些摘要和缓存需要重建。作者选择：

1. 在当前分支向后传播；
2. 从该位置创建新分支；
3. 仅修改文字，不改变 Canon；
4. 放弃修改。

提交后保留旧版本和来源链，可比较和回退。

## 8. 导入长篇

导入过程显示进度和不确定性：结构切分 → 实体聚类 → 事件/状态/知识候选 → 冲突 → 作者确认 → 摘要/索引。系统优先确认高影响事实，不要求作者一次审核所有提取项。

同名人物、别名、时间跳跃、未明确叙述者和不可靠叙事标为待确认。原文永远保留为可回查来源。

## 9. Review

审查输出分栏而不是单一总分：

- Canon/连续性：与哪个版本或事实冲突；
- 人物知识/POV：是否提前知道、错误归因或越权泄密；
- 因果与状态：变化是否有事件支撑；
- Thread：承诺是否建立、发展、兑现或长期遗忘；
- Scene Function：是否实现作者意图；
- Style：与当前 Style Profile 的差异；
- Context：问题是否来自缺失、过时或污染的输入。

作者可以说“这是故意的”，将其记为限定范围的意图或经验，而不是让系统重复报错。

## 10. Library 与素材复用

从 Library 导入素材时显示原版版本和导入方式。故事内变化属于 Story Instance。想把新变化提炼回 Library 时，系统先抽象掉故事专属经历，生成独立素材候选并展示来源。

两个故事可以从同一素材开始并独立发展。Library 升级只通知和比较，不自动覆盖。

## 11. Style Learning

作者选择自己的样本、目标作品或明确授权文本。系统展示观察到的词汇、句式、段落、叙事距离、对话、修辞、情绪和格式特征，并允许逐项关闭或限制作用域。作者修订可以形成新候选。

Style Profile 是写作指导，不是作者人格模型，也不是故事事实。

## 12. 恢复与交接

重新打开作品时，恢复包只包含：当前分支/版本、最后编辑位置、未提交草稿、待处理提案、活跃线程、最近决定和已知冲突。长篇资料按当前任务再检索，不复制一个不断膨胀的“完整记忆提示”。

## 13. 最小纵向切片

首个可用版本只需支持：

1. 创建作品与人物/规则；
2. 建立 Scene Mission；
3. 保存场景正文和版本；
4. 按 POV/时间编译 Context Packet；
5. 调用一个模型生成草稿；
6. 提取并展示候选变化；
7. 作者接受后提交 Canon；
8. 失效相关摘要并能回查来源。

Planning 全视图、向量检索、图谱、多 Agent、云协作和发布平台适配都可以后置。纵向切片必须先通过人物秘密、过时批准、跨故事污染和失败恢复用例。
