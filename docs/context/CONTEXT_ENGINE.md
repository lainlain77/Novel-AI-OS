# Context Engine 设计与验证计划

Status: proposed
Sources: SRC-002, SRC-003, SRC-004

目标：为当前创作/分析任务提供相关、可追溯、范围正确的上下文。没有选定 Long Context、RAG、Graph RAG 或 Hybrid，没有已完成的性能比较。

## 查询与上下文包候选契约

查询应能说明任务、故事/分支、Canon 基线、时间/场景、使用者视角、允许的素材/草稿范围及预算。系统要区分“AI 作为作者助手可读完整资料”和“正在生成的角色台词只能依赖角色所知”。

上下文包建议包含：

- 必要约束和确认事实，附来源 ID、版本和位置。
- 明确标识的计划、草稿、素材与角色信念，不能混称事实。
- 相关关系/事件及各自有效范围。
- 缺失项、互相冲突的证据、被截断项及失效来源。
- 查询的范围和基线，使输出可以复查。

预算不足时先保留安全的范围/来源标识和关键约束；若必要事实无法装入，应报告不完整，不声称检索已覆盖全部。具体优先级需要实验。

## 候选对比

| 候选 | 需验证的假设 | 主要检查 |
| --- | --- | --- |
| Long Context | 任务范围内原文可直接装入并被正确使用 | 长度增长后的遗漏、成本与来源定位 |
| RAG | 检索能找到必要事实片段 | 关键事实召回、错故事/错版本混入 |
| Graph RAG | 关系扩展能补足多跳关联 | 关系维护、过时边和范围控制 |
| Hybrid | 多种方法组合有足够额外收益 | 实际收益是否抵消复杂度和预算 |

上表是要检验的假设，不是来自实验的结果。技术/模型选型时另建可复查来源和日期，不引用不存在的研究产物。

## 小规模试验设计

先用 S1–S6 制作人工可检查的任务集，每题列必须包含、不得包含、预期缺口和来源。至少覆盖两部小说同名素材、角色误信、时间回溯、不同分支、Canon 改动后旧摘要和预算不足。

记录必要事实覆盖数/总数、越范围条目数、来源可定位条目数/总数、冲突暴露情况及实际使用预算。安全边界用例中不得混入另一故事事实，不得把旧摘要或推断提升为 Canon。性能阈值、语料规模及成本上限待 Q002，不能凭空填写跑分。

## 更新和失效

摘要/索引应记录来源版本。Canon 或 Library 版本变化后，派生内容标记为待重建或在读取时核验。旧摘要与新正式事实矛盾时，展示过时来源并按明确版本重新读取，不自动修改事实或静默混合。

运行时失效机制和存储仍待 Q004/Q008；项目 Manifest 是仓库文档地图，不是已经实现的小说检索引擎。
