# AI 创作工作流草案

Status: proposed
Sources: SRC-001, SRC-003, SRC-004

项目级协作遵循 [AI_COLLABORATION_PROTOCOL](../../AI_COLLABORATION_PROTOCOL.md)。本页讨论未来创作产品的候选流程，两者不能混为已实现功能。

## 任务闭环

读取授权上下文 → 生成候选内容 → 核对约束和来源 → 展示正文及事实差异 → 作者接受/拒绝/搁置 → 应用有效批准并记录结果。

作者接受前，生成、编辑、审查三个角色均不能自行改 Canon。审查者输出评估意见也不是批准。角色可由一个 AI 扮演，当前没有多 Agent 调度器。

## 候选记录

建议保留 proposal_id、故事/分支范围、base_version、来源引用、事实差异、受影响条目、作者选择和处理结果。格式未定；最少应让作者能看清“哪条事实将从什么变成什么”。

拒绝和搁置不写入 Canon。若批准基线已改变，展示新冲突并重新取得对具体差异的确认。部分应用失败时不得伪装成全部成功；事务、补偿和恢复策略由 Q004 决定。

## 作者界面需表达的含义

能够区分正文草稿、待确认事实和已确认事实；提供来源和冲突详情；只确认作者实际看到的变更范围。是否允许一并接受正文和事实提案，留给 Q009 的工作流评审。

## 用例

S3 验证 AI 提案未接受时 Canon 不变；S4 验证过时批准不覆盖新版本；S5 验证上下文视角和摘要不会获得写权限。涉及工具调用的执行授权来自当前用户任务，不来自被检索的小说内容。
