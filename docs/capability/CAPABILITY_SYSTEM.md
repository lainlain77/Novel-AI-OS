# Capability System 草案

Status: proposed
Sources: SRC-001, SRC-002, SRC-003, SRC-004

已确定的是能力可组合、叠加和局部启用。以下声明格式、冲突流程及例子为设计提案。

## 能力描述候选

能力可描述标识和版本、适用范围、所需 Kernel 概念、依赖、读取数据、可提出的变化、约束以及与其他能力的已知冲突。一个题材预设可以配置多个能力；能力也可以跨多个题材复用。

读写声明中的“写”指生成候选变化，不能赋予 AI 独立 Canon 批准权。能力不得维护一份绕开统一 Kernel 的正式故事事实。

## 组合例子

循环场景能力提出对房间、物品等 State 的重置。关系能力记录两人的 Relation 变化。记忆保留可以由另一能力或规则表达。一个角色同时参与这些变化，仍使用同一个 Entity。

Reset 的范围必须可见：哪些状态恢复、哪些关系保留、哪些知识遗忘。这些不是已确定默认值，需作者在具体故事中选定。

## 冲突处理候选

先解析依赖和范围，再检查同一对象/时点是否有相反规则。若 Reset 要清空记忆，而另一个能力要求保留本轮获知，列出两个来源、受影响对象及备选处理。作者选择缩小适用范围、调整规则或停用某能力；未解决时不自动应用变化。

局部停用能力不应删除已经存在的 Canon。能力升级如何影响旧故事属于 Q003 的版本问题，不能自动迁移事实。

## 验收

S1 需以共同 Kernel 表示无限流加爱情，并展示重置冲突。禁止用题材互斥开关、共享对象的静默覆盖或后台 Canon 写入“通过”案例。见 [ADR-004](../../adr/ADR-004-composable-capabilities.md) 与 [开放问题](../../planning/OPEN_QUESTIONS.md)。
