# 接手验收

Status: active_checklist

目标是让接手者依靠仓库回答问题并开展下一步。检查分三个层次，不能混称全部通过。

## A. 结构检查

执行 `node scripts/validate-memory.mjs`。检查登记文件存在且覆盖实际文件、Markdown 相对链接和锚点、必读顺序、六项原则到 accepted ADR 的映射、ADR 状态和来源、提案不进入已确定决定、任务/交接/问题的一致性。

修改检查器时执行 `node scripts/validate-memory.mjs --self-test`，故意破坏路径、状态、来源、任务或登记关系，要求检查器报错。正常检查需退出码 0，失败退出非零。

## B. 内容演练

从 AI_START_HERE 出发，回答并引用具体文件：

| ID | 接手者必须能回答 | 通过标准 |
| --- | --- | --- |
| H1 | 目标及实际完成到哪里 | 明确文档基础/设计草案/无产品实现 |
| H2 | 六项原则和原因是什么 | 每项指向 accepted ADR，能解释隔离/Canon 约束 |
| H3 | 哪些是提案，为什么没定案 | 识别 ADR-007/008、Context 选型及字段/技术栈 |
| H4 | 讨论是否完整，来自哪里 | 识别有限摘录、超时、基线以及 Q001 |
| H5 | 下一步具体做什么 | T002 的输入、步骤、产出、依赖和完成标准 |
| H6 | 怎样避免资料再次漂移 | 修改前 P1–P6、结构检查、主记录同步、最新交接 |
| H7 | 未确认建议和污染风险如何处理 | 使用 S2/S3/S4/S5 解释禁止的变化，不声称已有运行时 |
| H8 | 发布成功怎样核实 | 区分本地保存与远端提交，检查分支/提交和版本 |

在 AUDIT_LOG 记录答案摘要及来源。只找到标题、不读到能回答问题的内容，不算通过。

## C. 独立接手演练

将精确仓库版本、AI_START_HERE 和本文件交给未读对话历史的协作者。要求按 B 回答并提出 T002 的第一个具体动作；记录协作者、版本、答案、失败项、修复及复测。

本轮同一协作者的检查不替代 C。C 的一次通过也不证明所有 AI 都能接手；环境读取能力和 Q001 历史范围单独声明。资料有更新时按影响重测相应用例，不无限重复无变化检查。

## 完成判断

A/B 通过可称“已建立并自检项目记忆初版”。C 完成且历史范围明确后可称“该版本通过独立接手验收”。不能在 Q001/Q010 仍开放时称“全部历史已保存，任意 AI 必然无缝接手”。
