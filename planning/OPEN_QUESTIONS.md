## Q001 — 历史补录

现状：仅 SRC-002 有限摘录，完整会话两次读取超时；更早分支和附件未取得。可用材料足够整理当前六项原则，但不足以恢复全部历史。候选入口：重新读取原会话、用户已有导出或原始资料；不得用生成内容填补缺失。

下一步：取得材料后逐段登记来源、对比现有摘要、记录新增/冲突/重复内容。关闭条件：用户希望保留的历史范围可明确列出，已取得材料全部核对；仍不可恢复的部分经作者确认范围后保留缺失清单。影响：阻塞“全部历史已保存”的声明，不阻塞有来源标识的 T002。

## Q002 — Context 选型

研究基线与 T005 百万字合成实测已完成。权限硬过滤 + FTS5 在精确查询上 45/45、泄漏 0/60、p95 66.762 ms；无共享词同义查询 0/5。ADR-013 已决定在 Policy Gate 内加入可替换语义通道，FTS 保持 fallback。

T006 需在扩展语义集上比较 embedding/hybrid；自然小说、模型生成质量和供应商变化仍需注明数据/版本/日期。GraphRAG 继续等待多跳失败证据。

## Q003 — 能力组合

候选：显式读写/约束声明，作用域限定，依赖解析和冲突报告；默认优先级或覆盖语义未定。下一步用 S1 构造 Reset 与关系/记忆保留冲突。

关闭条件：依赖、冲突、局部启停、升级影响能用统一契约表达，有正常和冲突样例；作者接受涉及故事语义的选择。相关 [Capability 草案](../docs/capability/CAPABILITY_SYSTEM.md)。

## Q004 — Canon 版本与批准

首版结论：采用 ChangeProposal、baseRevision、manifest hash、全量预检查和原子事务；旧批准转 stale，部分接受生成新 proposal。T003 已验证未确认不写入、成功提交、旧批准拒绝、失败回滚和摘要失效。

首版由 [ADR-009](../adr/ADR-009-canon-transaction.md) 定案。多人并发合并、离线同步和跨设备恢复转 Q014；发现事务模型不适用的新证据时重开此问题并新增替代 ADR。

## Q005 — 知识与视角

首版结论：显式 knower/visibility/sensitivity/narrative cursor，并在检索排序前执行确定性 gate。T003 已验证角色误信、他人知识、作者秘密、读者 cutoff 和同名作品/分支隔离。

首版由 [ADR-010](../adr/ADR-010-knowledge-gate.md) 定案。自动抽取的知识标注、读者可推断性和长篇泄漏评估仍开放，纳入 Q011。相关 [实现记录](../docs/technical/VERTICAL_SLICE_T003.md)。

## Q006 — Library / Blueprint

候选：复制快照保留来源；固定版本引用加覆盖。下一步演练双故事实例、原版升级、故事改编提炼回素材库。

关闭条件：明确 Blueprint 定义、身份/版本/来源、实例隔离、升级及独立导出规则，S2/S6 满足 P5/P6，ADR-007 经作者接受或被有理由的替代方案取代。

## Q007 — 技术实现

本地首版已选择 TypeScript 模块化单体与 SQLite/FTS5，并由 [ADR-011](../adr/ADR-011-local-storage-retrieval.md) 定案。模型供应商、最终 UI 和云部署仍未决定。

T003 已提供代码和运行证据，不再只是由文档脚本推断技术栈。T004 继续验证 Model Adapter 和最小作者界面；规模或部署失败可通过新 ADR 替换适用范围。

## Q008 — 记忆与工作流契约

结论：项目记忆、Library、Canon、草稿和派生资料保持逻辑边界；摘要/索引是可失效派生资料。T003 已实现来源 revision、跨 scope gate 和依赖失效。

[ADR-008](../adr/ADR-008-memory-first-architecture.md) 已定案，[ADR-009/010](../adr/README.md) 补充提交与访问边界。后续缓存和重建性能由 Q002/Q011 继续测试。

## Q009 — 作者操作路径

T004 已实现任务/POV → Context Inspector → 草稿/建议 → Canon Inbox → 接受/拒绝的本地工作台。界面显示来源 revision、入选原因、预算、敏感级别和 Canon revision，模型层不能直接写入。

自动测试已覆盖接受与拒绝。完整编辑、diff 高亮、stale 冲突交互、撤销、可访问性和作者实际试走仍开放；见 [T004](../docs/technical/WORKBENCH_T004.md)。

## Q010 — 独立接手测试

现状：本轮同一协作者可做静态检查和入口演练，但不能冒充独立新会话验收。下一步把已发布版本及 [验收说明](../docs/quality/HANDOFF_ACCEPTANCE.md) 交给没有对话历史的协作者，只提供仓库入口。

关闭条件：记录协作者、精确版本、实际回答、引用和发现的缺口；核心问题均能从仓库回答，修复失败项并复核。单次成功也不等于证明所有 AI 的能力；Q001 的历史完整性单独判断。

## Q011 — 评估夹具与门槛

T003 建立小型安全回归；T005 增加固定 seed 的 1,072,358 字符、2,131 记录、70 次编译基准。精确召回、零泄漏、来源、延迟和失效门槛通过，语义词法基线 0/5。自然小说、Library 升级、旧章重写、真实 tokenizer、语义/生成质量、多次运行分布和人工标注仍待扩充。

## Q012 — 隐私与模型数据策略

需要决定哪些正文/秘密可发送云模型、日志默认保存什么、如何脱敏、如何删除或导出、供应商保留策略怎样展示，以及本地模型降级路径。ContextGrant 必须延伸到日志、缓存和派生摘要。关闭需威胁模型、默认策略和作者可理解的控制界面。

## Q013 — Skill 与插件治理

七技能 V1.0 完成方法审计，原包逐文件、hash、脚本、许可证和重复谱系仍待复核。外部 Skill 默认只读授权 Context Packet 并输出结构化建议。关闭需 manifest schema、静态审计、沙箱、版本锁定、升级差异、撤销和恶意内容用例。

## Q014 — 协作与同步

首版按单作者本地优先实现。多人实时编辑、Canon 冲突合并、权限继承、离线同步和远端加密后置。关闭需明确协作对象、冲突语义、恢复目标和服务部署边界；不得用普通 Git 合并假装解决故事语义冲突。
